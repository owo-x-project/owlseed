# owlseed

An immutable Agent Skill that gives an AI agent a **work lifecycle**, four named
**contracts**, and an **acceptance gate**, so that it can work on a project
continuously and consistently across sessions.

owlseed holds no project-specific knowledge. It fixes names and contracts, never
paths, formats, or means of verification. Everything specific to your project grows
around it -- generated by the agent the first time it germinates, and improved by
experience after that. Four core skills are created with fixed names:
`owlseed-compass` (purpose and scope), `owlseed-state` (where we are and how to get
back), `owlseed-verify` (what "verified" means here), and `owlseed-grow` (forming,
improving and pruning capabilities). Their contents are yours, not owlseed's.

## The problem it solves

An agent starts every session from nothing. It rediscovers what the project is for,
guesses where the work stopped, and settles on its own definition of "done" -- a
different one each time. Work that ends mid-way leaves nothing the next session can
resume from, and what the agent learned along the way is lost with the context window.

Instruction files help, but nothing governs them: they accumulate, contradict each
other, and go stale, because there is no rule for how a capability is formed, verified
or pruned.

owlseed supplies the fixed points that are missing. One work unit at a time, through
seven stages:

| Stage | The question owlseed asks |
|---|---|
| Germinate | Where are the purpose, the state, and the means of verification? |
| Orient | Where are we now? Is the foundation intact? |
| Select | What is the next single unit? Does it serve the purpose? |
| Act | Do we have the capability? If not, is it worth building? |
| Verify | Can we call this verified? On what evidence? |
| Sediment | Which layer does this experience belong to? |
| Close | Can the next session pick this up? |

Nothing a project writes can override those rules, and every change to a capability
passes the same acceptance gate.

## Install

owlseed is a plain [Agent Skills](https://agentskills.io) skill: Markdown only, no
scripts, no experimental frontmatter fields. It works in any runtime that implements
the specification.

**Any runtime, via the skills CLI.** This detects the agents you have installed and
links the skill into each one's discovery path.

```sh
npx skills add owo-x-project/owlseed
```

**Claude Code, via the plugin marketplace.** Installed this way the skill is
namespaced, so you invoke it as `/owlseed:owlseed`.

```
/plugin marketplace add owo-x-project/owlseed
/plugin install owlseed@owlseed
```

**By hand.** Clone once and link it wherever your runtime looks. `.agents/skills/`
covers Codex CLI, Gemini CLI, Cursor, Cline and OpenCode; Claude Code needs
`.claude/skills/`, which does not read `.agents/`.

```sh
git clone https://github.com/owo-x-project/owlseed ~/src/owlseed

mkdir -p ~/.agents/skills ~/.claude/skills
ln -s ~/src/owlseed/skills/owlseed ~/.agents/skills/owlseed
ln -s ~/src/owlseed/skills/owlseed ~/.claude/skills/owlseed
```

**The first time, invoke it explicitly** -- run `/owlseed`, or just tell the agent to
read the owlseed skill and start. Before germination there is nothing in the project
that points at owlseed. From then on the agent reaches for it on its own.
