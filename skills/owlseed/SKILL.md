owlseedは読み取り専用。改善する価値があると判断したものはコアSkillか派生Skillであって、owlseedではない。

現在位置は記憶ではなく owlseed-state から読む。段階の出口で state を更新してから次へ進む。完了・検証済み・収束は state に根拠付きで記録されたものだけを認め、会話中の宣言は判定ではない。

コアSkillの契約の正本は、owlseed の assets にある骨組みの保証節である。照合は必ずそちらに対して行い、プロジェクト側の複製に対しては行わない。

発芽。owlseed-compass / owlseed-state / owlseed-verify のいずれかが無ければ、references/germinate.md に従って形成する。目的が読み取れなければ人間に確認し、推測で埋めない。**進む条件: 3つのコアSkillが存在し、骨組みの保証節すべてに答えられる。**

定位（state, verify）。state を読み、現在位置・待っているもの・前回の収束が完全だったかを確定する。state が記録している版が上記と異なれば、各コアSkillを骨組みの保証節と照合し、答えられない保証を沈殿待ちに積む。**進む条件: 現在位置が state にあり、土台が verify の基本確認を通っている。通らなければ修復を作業単位として先頭に積む。** 基本確認が未定義なら、発芽に戻らず verify の改善候補として沈殿待ちに積む。

選択（state, compass）。人間の依頼も待ち行列の単位も、まず state に登録し、compass で範囲を判定する。**進む条件: 未検証の単位がちょうど1つ進行中で、1セッションで検証まで届く大きさである。**

実行（派生Skill）。前文を持つSkillだけを使う。必要な能力が無い場合は、繰り返すか独立した能力として保持する価値がある時だけ、references/grow.md に従って形成する。目的・範囲・検証契約の変更は決定として記録する。途中で見つけた改善は、今の単位の結果に影響する、後回しにすると手戻りが出る、誤った状態のまま進むと後の作業に及ぶ、重要と判断した、のいずれかの時だけ即時に反映し、他は沈殿待ちに積む。**進む条件: 成果があり、途中経過が state に記録されている。**

検証（verify）。verify の手段で確かめ、可能なら成果を作った文脈とは別の文脈で評価する。失敗は実行へ戻す。同じ原因で繰り返すなら選択へ戻して分割する。**進む条件: 検証済みか差し戻しかが、根拠付きで state に記録されている。**

沈殿。経験を持ち主の層へ返す。名前のついた再利用可能な手順はSkillへ、いつ何が起きたかは owlseed-state へ、プロジェクト理解は AGENTS.md へ提案として渡す。Skillに触れる前に references/grow.md を読む。**進む条件: Skillへの変更がすべてゲートの記録を持つ。**

収束（state）。**進む条件: 未記録の作業途中が無く、一覧に残っている単位がある限り完了と言っていない。** 対話では会話が終わる時に収束し、自律では単位ごとに収束して定位へ戻る。疑問は対話なら即質問し、自律なら記録して別の単位へ移る。

優先順位は owlseed ＞ コアSkill ＞ 派生Skill。プロジェクト側もowlseedを上書きできない。矛盾したら上位に従い、矛盾そのものを owlseed-state に記録する。

委譲しても検証は省けない。

references/grow.md — Skillの形成・改訂・統合・廃止・取り込みと、受入ゲート
references/germinate.md — コアSkillが揃っていない時の形成と再構成
references/guidance.md — 根拠のある推奨。規範ではない。状態の形式や検証手段を初めて決める時に読む
assets/ — コアSkillと派生Skillの複写元になる骨組み
