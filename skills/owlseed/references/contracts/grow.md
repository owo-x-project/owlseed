# 契約: owlseed-grow

## 役割

形成・改善・剪定。経験を正しい層へ返し、L1を育てる。受入ゲートの執行者。

## 保証すべきこと

- 経験（作業の結果、失敗、繰り返し現れた手順）がどの層へ返すべきものかを判定できる
- ある能力を形成・改善する価値があるか（反復性または保持価値）を判定できる
- L1の変更が受入ゲートの7条件を満たすかを判定し、判定理由を `owlseed-state` に記録できる
- 改善が以前の保証を壊していないかを、`owlseed-verify` の記録を根拠に確認できる
- 使われていないSkill・重複するSkillを統合・廃止候補として挙げられる（剪定）
- 外部Skillを派生Skillとして取り込める（薄いアダプタから始めてよい）
- 生成・改訂するSkillに `preamble.md` の前文を付けられる
- 発芽時に契約からコアSkillを生成できる
- 版移行時に既存Skillから新Skillを再構成できる
- owlseedが読まれていなければ、まずowlseedを読ませる

## 禁止

- 受入ゲートを通さずにL1を変更する
- owlseedを変更する
- L3（AGENTS.md）を提案なしに書き換える

## 参照される段階

発芽（コアSkillの生成）、実行（能力が無い時の形成判断、外部Skillの取り込み）、沈殿。

## descriptionの雛形

```
<プロジェクト名>のSkillを形成・改善・整理する。作業で学んだことを残したい時、繰り返す手順をSkillにしたい時、既存Skillを直したい時、外部Skillを使いたい時、Skillが増えて整理したい時、経験をどこに記録すべきか迷う時に使う。owlseed配下。
```

## プロジェクトが埋めること

- このプロジェクトでの「反復性」の判断基準（何回で切り出すか）
- 剪定の基準（どれくらい使われなければ候補にするか）
- 外部Skillの取り込み方（アダプタの置き方）
- L3への提案の出し方（人間にどう見せるか）

## 生成時の注意

growは自分自身も改善対象にできるが、その変更も受入ゲートを通す。特に条件6（owlseedを侵害しない）は、grow自身の改訂で最も破られやすい。
