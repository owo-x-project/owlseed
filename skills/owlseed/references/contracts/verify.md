# 契約: owlseed-verify

## 役割

検証済みの定義。「この成果は検証済みと言えるか」「何を根拠に言えるか」に答える。手段はプロジェクトごとに異なるため、owlseedは手段を指定しない。

## 保証すべきこと

- ある作業単位が検証済みか、何を根拠に言えるかを答えられる
- このプロジェクトに検証手段が定義されていなければ、作業より先に手段を確定させる（未定義のまま作業を検証済みにしない）
- 定位で使う「土台が壊れていないか」の基本確認を持つ、または未定義と明記する
- 過去に通った検証の記録を保持し、受入ゲートの条件3（保証を壊さない）に提供できる
- 生成と評価を分ける方法（別セッション、サブエージェント、要件の再読）を提示できる
- owlseedが読まれていなければ、まずowlseedを読ませる

## 禁止

- 根拠なしに検証済みとする
- 検証手段を、決定として記録せずに緩める

## 参照される段階

発芽（手段の確定または未定義の明記）、定位（基本確認）、検証。

## descriptionの雛形

```
<プロジェクト名>で「検証済み」と言える条件と手段を保持する。成果が完成したか判断する時、テストや確認の方法を知りたい時、土台が壊れていないか確かめる時、変更が以前の動作を壊していないか確認する時に使う。owlseed配下。
```

## プロジェクトが埋めること

- 検証手段の一覧（自動テスト、手動確認、目視、外部レビュー等。作業単位の種類ごとに異なってよい）
- 基本確認（土台の健全性を短時間で確かめる手順）
- 検証結果の記録先と形式（根拠として `owlseed-state` から参照される）
- 生成と評価を分ける方法

## 生成時の注意

手段が無いプロジェクトでは「目視で確認し、確認したことを記録する」でも手段として成立する。重要なのは手段の強さではなく、根拠が記録されることである。
