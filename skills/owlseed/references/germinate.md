# Germinate and rebuild

Do this when a core skill is missing. A renamed, combined or split core skill also counts as missing. Do it only when a human can answer.

1. Copy the matching template from assets into the place where the project keeps skills. Do not change the name or the headings.
2. Look for material. A skill that carries the core note at the top is an old core skill; use it as material. A document without the note gives only its content.
3. Fill in every part in angle brackets. Keep the lines above them; they say what owlseed asks for under that heading. Fill from the project what the project can tell you: where records go, the basic check, the ways to check. Ask a human for what only a human knows: the purpose, what is out of scope, what a human must decide, and which kinds of work there are and how each should go. Take one heading at a time. Show what you guessed, and let the human correct it. Do not move to the next heading until the human agrees. Write one line per answer where you can. Write the answers in the language the project uses, but keep the headings and the lines owlseed wrote in English, as they are in the template. Make sure no angle brackets remain.
4. Check gate conditions 3 and 7 only. Condition 3: every heading of the template is present and filled, and the lines that say what owlseed asks are still there. Condition 7: keep the old skill aside until the new one fills every heading, and only then delete it. The other conditions in references/gate.md do not apply here.
5. Record the human's agreement to each core skill as a decision, and the owlseed version, in owlseed-state.

Germination may finish without a way of checking. Then write "not defined" in owlseed-verify, and settle it before the first work unit.

If AGENTS.md exists, read it as material for understanding the project. If it also holds rules, procedures or state, leave them for now and add them to the improvement list in owlseed-state.
